# Protocol 1 extraction audit

Source: Gao et al., IACR ePrint 2021/1674, Appendix B, equations (29)–(45).

## Independent findings

Two independent reviews found no sign/order error in the implemented pairwise algebra:

- `y = x0 - x1`;
- `yG = Com(x0*M1 - x1*M0; x0*r1 - x1*r0)`;
- `yE = Com(h0 - h1; z0 - z1)`;
- `yF = Com(x0*h1 - x1*h0; x0*z1 - x1*z0)`;
- for S=2, `delta = zeta0 - zeta1`, `delta*b1 = M0-M1`, and `delta*b0 = zeta0*M1-zeta1*M0`.

No challenge difference is inverted.

## Implemented audit hardening

- The two-level tree rejects every commitment count other than `S=2`.
- Standalone second-layer extraction accepts optional fixed-`zeta` metadata and rejects inconsistent metadata.
- Every three-transcript family now derives all `(0,1)`, `(0,2)`, and `(1,2)` pairwise openings.
- Each pair is recomputed independently and compared.
- Reversing a pair is checked to negate the relaxation, message, and randomness.
- The third transcript is checked against the extracted openings rather than merely being parsed.
- Test fixtures include tampering, duplicate challenges, dimension errors, and reversed-pair checks.

## Important limits

The test suite is still not a proof. Earlier fixtures were largely self-consistency tests; the family path remains generated by the local builder/verifier. The next independent-test requirement is a hand-constructed accepting transcript family produced directly from the published equations, without calling `build_protocol1_ring_transcript`.

The integer audit checks recorded unreduced identities and final aggregate canonical representatives. It does not prove that every intermediate negacyclic multiplication or addition avoids modular wraparound. In particular, a complete audit must track `h`, `x*h`, `x*z_g`, challenge powers, and every aggregate before reduction.

No result here establishes HMC binding, knowledge soundness, exact Gaussian statistical distance, SHVZK, Fiat–Shamir security, concrete Module-SIS/Module-LWE security, or production readiness.
